# 倒数日 CountingDown

Windows 桌面角落的**倒数日小组件**。基于 **Electron + Vue 3 + Element Plus** 构建：桌面上是一个可自由调外观的透明无边框卡片，托盘里有图标，设置界面是完整的 Vue 界面。

## 功能一览

| 能力 | 说明 |
| --- | --- |
| **倒数日列表** | 设置界面首屏即列表，可新增 / 编辑 / 复制 / 删除多项，其中被标记「桌面」的那一项显示在桌面角落 |
| **单项可覆盖、留空跟随全局** | 每项可单独设置日期类型、目标日期、副标题、状态文案、天数单位，以及**独立的外观**（背景色/圆角/内边距/不透明度/字号/颜色/字重/字距/字体）；没开启或留空的字段一律跟随全局 |
| 桌面角落显示 | 无边框 / 透明 / 置顶窗口，`skipTaskbar` 保证**永远不进入任务栏** |
| 四角停靠 + 可拖动 | 左上 / 右上 / 左下 / 右下任选；开启「允许拖动」（托盘右键菜单或「全局设置 → 布局」）后可直接用鼠标拖动组件，松手时自动吸附到最近的角落并把位置换算成偏移量，组件**悬浮时依然不显示任何按钮** |
| 托盘图标 | **左键单击** = 显示/隐藏倒数日；**右键** = 菜单（设置、吸附到右上角、允许拖动、置顶、开机自启、退出）；**双击** = 打开设置 |
| 全局快捷键 | 默认 `ScrollLock`，可在设置里录制任意组合键（含 F1–F24、方向键、小键盘等），也可清空 |
| 日期语义 | 「每年重复的纪念日」与「一次性日期/时刻」，全局有默认值，单项可覆盖 |
| 显示模式 | 四档：只显示天数 / 天 + 时 / 天 + 时:分 / 天 + 时:分:秒（后三档实时跳动，精确档还能去掉天数部分） |
| 状态文案 | 未来 / 当天 / 已过 三段文案可自定义，支持 `{days}` 变量；当天默认「就在今天！」，过期默认「已远去」 |
| 全局外观自定义 | 组件不透明度、背景色 + 透明度、圆角、内边距、卡片宽度、边框粗细/颜色、阴影强度/颜色、四段文字（标题/大数字/副标题/状态）各自的字号、颜色、字重、字距，以及字体族（下拉里显示完整的 CSS `font-family`） |
| 预设主题 | 午夜蓝 / 晨雾白 / 樱花粉 / 极客绿 / 纸质便签，一键套用全局外观（已单独覆盖外观的项不受影响） |
| 实时预览 | 全局设置页顶部与每项的编辑页内都有真实渲染的预览 |
| 开机自启 | 设置里开关（默认关闭），或在托盘菜单勾选；启动时隐藏到托盘 |
| 中英双语 | 设置界面、托盘菜单均可切换 简体中文 / English |
| 点击穿透 | 卡片外的透明区域不拦截桌面点击，不影响桌面图标操作 |
| 旧配置迁移 | 首次启动会自动把旧版「单个倒数日」配置转成列表的第一项，文案上提为全局默认，不丢设置；旧版存在 `behavior.opacity` 里的不透明度也会搬到 `appearance.opacity`（组件不透明度已归入外观） |

```bash

pnpm install

# 生成托盘 / 应用图标（已随仓库生成，需要 Windows PowerShell 时才重跑）
pnpm run icon

# 开发模式（渲染层热更新）
pnpm dev

# 类型检查
pnpm run typecheck

# 构建产物
pnpm run build

# 打包为安装包（NSIS）
pnpm run dist
```

>    Electron 二进制不再自动下载。

## 使用方式

1. `pnpm dev` 启动后，屏幕右上角会出现倒数日卡片，同时托盘出现日历图标。
2. **托盘左键单击** 或 **按 ScrollLock** 开关倒数日显示。
3. **托盘右键** 打开菜单，或直接双击托盘图标打开设置。
4. 设置界面左侧为两级导航：
   - **倒数日列表**（首屏）：每行左侧的单选按钮决定「哪一项显示在桌面」；被停用的项会归到底部
     「未启用（不能被选为桌面显示）」分组，**不能被选中**，需要先点「启用」。
     点行内任意位置进入该项的**编辑子页**。
   - **全局设置**（折叠分组）：日期与文案 / 外观 / 布局 / 行为 / 预设主题 / 系统集成 / 关于。
5. 桌面卡片**悬停时不显示任何按钮**；位置与偏移在「全局设置 → 布局」。
6. 开启**允许拖动**（托盘右键或「全局设置 → 布局」）后，直接按住卡片拖动即可：
   松手时自动选择最近的角落并把窗口位置换算成偏移量写回配置，设置里的数值随即同步；
   拖动范围会保证卡片始终完整留在屏幕工作区内。

### 编辑子页

- 右上角是**保存**按钮（与「返回列表」同一容器），标题旁会显示「未保存的修改」标记。
- 编辑过程**不会即时写盘**：点保存才提交并返回列表；若有未保存修改时点「返回列表」，
  会弹出「保存并返回 / 放弃修改 / 继续编辑」三选一。
- 日期、文案**留空即跟随全局**：输入框的 placeholder 显示该字段**实际会生效的值**
  （单项 → 全局 → 内置默认 这条链路解析出来的结果）。
  - 日期：编辑页直接显示**实际生效的日期**；**没动过日期控件**就保持原样（继续跟随全局），
    **动过之后**才写入该项，此时可用标题下方的「跟随全局」清空回跟随。
- **副标题 / 状态文案**都是**标签式**切换：
  - 全局（「日期与文案 → 显示项」）是 `显示 / 不显示` 两个标签，默认显示。
  - 编辑页是 `跟随全局 / 显示 / 不显示` 三个标签，默认「跟随全局」；选了显示或不显示就覆盖全局。
- **外观区**：一个**总开关**控制是否覆盖；开启后每项左侧出现复选框，勾选哪项才显示哪项的输入控件。
  取消勾选即恢复跟随全局，因此没有「恢复全局设置」按钮。

### 组件渲染模式（重要）

Windows 上透明窗口依赖系统「透明效果」，而且**分层窗口在 `showInactive()` 之后有时不会重绘**，
DWM 会用不透明底填充它 —— 表现就是「组件一显示就出现一块浅色大背板，隐藏就消失」，
而**右键托盘弹出菜单（原生菜单会触发一次桌面重新合成）后背板又消失**。

程序做了三层处理：

1. **显示后强制重绘**：统一的显示入口 `showWidgetWindow()` 在 `showInactive()` 之后做一次 1px 位移抖动
   （`nudgeRepaint`），强制 DWM 重新合成。所有显示路径（启动、托盘左键、快捷键、设置里的「显示倒数日」、
   模式切换重建）都走这个入口，避免有的路径有修复、有的没有。
2. **自动检测系统透明效果**：启动时读 `HKCU\...\Themes\Personalize\EnableTransparency`；
   关闭时透明窗口会被画成不透明白块，此时自动切到**不透明兜底模式**（整个窗口即卡片 + 系统窗口圆角）。
3. **手动开关**：「全局设置 → 布局 → 使用透明窗口」，切换会重建组件窗口
   （`transparent` 只能在创建时指定），系统不支持时会给出提示。

两种模式共用同一套外观配置，区别只是窗口是否缩进 24px 以及要不要自己画阴影/边框。

> 排查记录：`capturePage()` 抓到的窗口一直是透明的（可见像素只覆盖卡片区域），说明问题出在
> 「窗口内容正确但系统合成不对」，而不是 CSS。因此没有去改绘制，而是补上强制重绘与不透明兜底。

### 拖动与偏移量

「允许拖动」（托盘右键菜单与「全局设置 → 布局」里的同名开关，两边实时同步）打开后，
按住卡片就能拖动组件：

1. 渲染层在卡片上 `pointerdown` 时上报**卡片相对窗口的位置**，主进程据此进入拖动；
2. 主进程按 16ms 轮询光标（透明窗口收不到可靠的鼠标移动事件），窗口位置 = 按下时的窗口位置 + 光标位移，
   并保证**卡片始终完整留在工作区内**（不是整窗留在工作区——窗口 624×600 比卡片大得多，
   按整窗限制的话卡片在纵向只能移动 480px，根本拖不到屏幕另一半）；
3. 拖动期间强制保持命中，否则光标一旦甩出卡片，点击穿透会让拖动直接断掉；`pointerup` / `pointercancel` /
   窗口失焦都会结束拖动；
4. 松手时按卡片中心选择**最近的角落**，再把窗口摆到「新角落 + 新偏移量」能还原出同一落点的位置，
   所以松手时卡片不会跳；偏移量随后写回配置，设置面板里的数值与参考基准立刻同步。

换算出的偏移量始终落在布局面板滑块的量程内，并且 `computeCornerPosition()` 能精确还原窗口位置
（回归脚本 `scripts/drag-check.cjs` 用真实鼠标消息拖动并断言 `ROUNDTRIP.ok`）。

## 全局与单项的关系

- **全局**：日期默认值、默认文案、全部外观（含**组件不透明度**）、显示模式、位置与偏移、是否允许拖动、托盘与快捷键。
- **单项**：名称、是否启用、可选的日期/文案覆盖、可选的外观覆盖（字体、不透明度、背景、四段文字样式）。留空（或未开启外观覆盖）的字段继续跟随全局。
- 「全局设置 → 预设主题」分两块：**我的预设**（把当前外观存成命名预设，可套用/删除）与**内置预设**。
  套用后已单独覆盖外观的倒数日不会被改动（列表里会标出「此项已覆盖外观」）。
- 位置支持**偏移量**：参考基准可在下拉中选择四个角（隐含预设）或「自定义」坐标，
  偏移量在此基础上叠加，实时生效并按屏幕分辨率限幅；用鼠标拖动后这里的数值会自动更新。

## 配置文件

配置由 `electron-store` 持久化在：

```
%APPDATA%\countingdown\config.json
```

- 设置界面的「系统集成 → 打开配置文件位置」可直接跳转。
- 「恢复默认设置」会重置全部配置（列表、外观、日期、行为、位置）。
- 主进程写盘后会把最新配置广播给所有窗口，因此**托盘菜单的改动会立刻反映到设置界面与桌面卡片**。

配置结构（`src/shared/types.ts` 为唯一的类型来源）：

```jsonc
{
  "countdowns": [
    {
      "id": "cd_xxx",
      "name": "元旦",
      "enabled": true,
      "target": { "mode": "annual", "date": "", "month": 1, "day": 1 },  // once 模式下 date 为空 = 跟随全局
      "text":     { "hint": "", "futureText": "", "todayText": "", "pastText": "", "unit": "" }, // 空串 = 跟随全局

  "target":     { "mode": "annual|once", "date": "YYYY-MM-DD[THH:mm]", "month": 1, "day": 1 }, // 全局默认日期
  "text":       { "hint", "futureText", "todayText", "pastText", "unit" },                     // 全局默认文案
  "appearance": { "fontFamily", "opacity", "background": {...}, "title": {...}, "count": {...}, "hint": {...}, "status": {...} },
  "behavior":   { "displayMode", "showDaysInPrecise", "showPastDays", "alwaysOnTop" },
  "runtime": {
    "widgetVisible", "toggleHotkey", "startAtLogin", "language", "theme",
```

## 关键实现说明

- **永不进入任务栏**：组件窗口创建时 `skipTaskbar: true`，并且在每次显示后又调用一次 `setSkipTaskbar(true)`；`window-all-closed` 不退出应用，靠托盘常驻。
- **总是浮在最前**：`setAlwaysOnTop(true, 'screen-saver')`，可在设置或托盘菜单关闭。
- **点击穿透**：透明窗口用 `setIgnoreMouseEvents(true, { forward: true })` 让指针事件穿透到桌面；由于本机实测 `forward` 并不派发事件，主进程改为**每 80ms 轮询一次光标屏幕坐标**并推送给渲染层，渲染层用 `window.screenX/Y` 换算成窗口内坐标做命中测试，指针落在卡片上时通过 IPC 临时恢复鼠标事件，离开立即恢复穿透——因此卡片的透明区域不会挡住桌面图标。
- **卡片定位**：`.cd-stage` 只负责四角对齐，卡片外层 `.cd-shrink` 绝对定位在 `24px` 安全区内（`top/right/bottom/left: 24px`）。窗口尺寸取 `624×600`，正好等于「安全区 576×552 + 2×24」，因此卡片到屏幕边缘的距离在四个方向都是 24px。
- **当天/过期判定**：不带时刻的日期按「整天」语义（当天 = 就在今天）；带时刻的日期到点即视为已过。
- **每年重复**：`annual` 模式只存月/日，若今年已过会自动滚动到明年，因此跨年无需手动维护。
- **跨 IPC 传配置必须去 Proxy**：`patchConfig` 会先把 patch 递归转成普通对象（`isRef` / `toRaw` 逐层处理）再发 IPC。把 Vue 的 reactive/reactive 数组直接丢给 `ipcRenderer.invoke` 会抛 `An object could not be cloned`，而且 `structuredClone` / `toRaw` 只处理最外层，嵌套 Proxy 依然失败。
- **编辑子页的草稿同步**：主进程每次写盘都会广播全量配置，如果无条件用广播值重载草稿，打字过程中会被回传覆盖。现在比较「草稿算出的项」与「props 里的项」，等价就跳过，只有真正的外部改动才重载草稿。
- **不要用 computed 初始化 reactive 草稿**：`reactive({ month: globalTarget.value.month })` 只在 `setup` 执行一次，而 store 是异步加载的，computed 之后更新草稿不会跟着变——这正是「目标日期总是回到 1 月 1 日」的根因。做法是在 `setup` 末尾调用 `syncFromItem(props.item)`，初始化与 `props.item` 变化共用同一条同步路径。
- **超大内容的等比缩放**：组件窗口固定 624×600，安全区为 576×552。当「精确模式 + 超大字号」等内容天然宽于安全区时（实测 110px 字号「95天02:46:11」需要 673px），渲染层会按 `available / natural` 给卡片容器加 `zoom`（**不是** `transform: scale`，因为 zoom 才会真正缩小布局盒子）。
  - **测量必须用布局尺寸**：zoom 作用在 `.cd-shrink` 上，`getBoundingClientRect()` 给的是缩放后的视觉尺寸，而 `scrollWidth` / `offsetWidth` 不随 zoom 变化。早先用视觉宽度与可用宽度比较，收敛点会偏大（约 `√(可用/自然)`），于是**显示到秒时文字比卡片还宽、卡片也顶出安全区**。现在按行取布局尺寸算出「内容自然宽度 + 卡片内边距与边框」作为缩放基准，一次算准。
  - **卡片的宽度上限按缩放换算**：`zoom ≠ 1` 时 Chromium 下 `.cd-shrink` 的布局宽度与视觉宽度不再严格等比，只靠 `max-width: 100%` 会允许卡片比安全区宽出几像素；因此缩小后额外把卡片的 `max-width` 设成 `可用宽度 / zoom`（布局 px），保证视觉上正好落在安全区内。
  - **卡片不得窄于内容**：`.cd-card` 带 `min-width: fit-content`，用户把「卡片宽度」设得比内容还窄时宁可卡片变宽，也不让文字溢出到背景之外。
- **卡片横向对齐**：卡片自身用 `align-items: center` 居中对齐，避免 flex 拉伸导致命中区域覆盖整条窗口宽度（这个坑已修，改动 `.cd-stage`/`.cd-card` 对齐时请留意）。

### 说明统一收进问号

原来的补充说明有两种呈现：标签右侧的「?」tooltip **和** 控件下方额外一行的灰色小字。
后者既占高度又把表单切得很碎，现在统一成前者：

- `FieldRow` 的 `hint` 只渲染成标签右侧的「?」图标 tooltip（`QuestionFilled` 图标，不再是灰底小圆点），
  控件下方的 `field-row__note` 已删除；确实需要常显示的提示用 `#note` 插槽传入。
- 卡片/分区标题右侧也提供同样的「?」，承接原来独立成行的说明：
  日期与文案（默认值说明、显示项、状态文案占位符）、预设主题（自定义与内置说明）、
  倒数日列表（列表规则）、系统集成（托盘说明）、布局（位置与偏移说明）、编辑页三个分区标题。
- 因此这些页面上原本的 `el-alert` 与说明段落已经全部移除（实测各页 `bottomNotes: []`、`alerts: 0`）。

### 深色主题图标对比度

`.el-button.is-text`（列表里的编辑/复制/删除图标按钮、各处链接按钮）在深色主题下用的是
Element Plus 的次要灰，暗到几乎看不见。现在深色主题下统一提到 `#c6cedd`（实测
`rgb(198, 206, 221)`，对深色底 ≥ 8:1），hover 用主色，禁用态单独给一个可见的灰。

### 外观覆盖（逐个勾选）

编辑页的「外观覆盖」是一个**总开关 + 逐项复选框**的结构：

- 总开关关闭时不写任何覆盖，`appearance` 保持 `{}`，控件区完全不渲染；
- 打开后每项左侧出现复选框（字体、不透明度、背景色、圆角/内边距、边框、阴影、四段文字样式），
  **勾选哪项才显示哪项的输入控件**，未勾选的继续跟随全局；
- 勾选时以当前全局值作为起点，取消勾选即删除该字段；
- 因为勾选框本身就是「是否覆盖」的开关，所以不再需要「恢复全局设置」按钮。

实测：总开关关 → `checkboxes: 0, styleEditors: 0`；开 → `checkboxes: 7, styleEditors: 0`；
勾选「大数字样式」→ `styleEditors: 1`；保存后只写入 `{"count": {...}}`，未勾选项不落盘。

### 倒数日列表的启用开关

已启用那一组**不再显示启用开关**（它们本来就是开着的），改成和未启用组的「启用」对称的
「停用」文字按钮；启用/停用之外的编辑、复制、删除统一为图标按钮，都不带 tooltip。
实测：两组各 4 个按钮，其中一个是「停用」/「启用」文字按钮，`tooltips: 0`。

Element Plus 的 `el-radio-button` 默认**不是**每个标签各画一圈边框，而是靠
`margin-left: -1px` + `box-shadow` 把相邻标签的边框拼在一起（第一段的左边框只由
`box-shadow` 提供），并且给首/中/尾标签分别设了单边圆角。

这带来两个坑：

1. 父容器只要有 `overflow: hidden`（我早先为修滑块溢出加的），**首标签的左边框就被裁掉**，
   看起来就是「边框被吞了」；换行布局下相邻标签还会叠边。
2. 圆角被拆成 `4px 0 0 4px` / `0 4px 4px 0`，最后一个是直角。

现在的做法（`settings.css` 里统一覆盖，不只修字重那一处）：

- 每个标签都是**独立圆角小按钮**：真实 `1px` 边框 + `6px` 圆角，`box-shadow: none`，标签间 `6px` 间距；
- 标签高度统一 `26px`（`.is-compact` 为 `24px`，用于样式编辑器里更紧凑的场景），字号 `12.5px`；
- `.el-radio-group` 允许换行并留 `8px` 行距；
- 圆角那条规则要用 `.el-radio-group .el-radio-button:first-child .el-radio-button__inner`
  这种**更高特异性**的选择器，否则压不过 Element Plus 自带的单边圆角规则；
- `.row__control` 上**不能**再留 `overflow: hidden`，滑块自己的溢出交给 `.slider-field` 处理。

实测（外观 / 日期与文案 / 行为 / 关于 / 编辑子页，共 88 个标签）：
圆角全部 `6px`、边框 `1px`、裁切 0、标签重叠 0、组内溢出 0。

### 滑块与颜色控件重构（左右重叠问题）

现象：外观页里左侧滑块的数值、右列设置项的文字会挤在一起，数值框里还出现滚动条。

量出来的根因有三条，都不是「文字本身重叠」：

| 根因 | 实测 | 处理 |
| --- | --- | --- |
| `el-slider` 的 `show-input` 内部是完整 `el-input-number`（**最小 130px**，自带滚动条） | 两列网格里轨道只剩 `101px`，输入框 `130px` 与轨道挤在一行 | 新增 `SliderField.vue`：**关掉 show-input**，改成同一行内一个只读数值块（44px 起） |
| 两列网格 `gap: 0 22px` 左侧为 0 | 左列控件右缘 `640`、右列标签左缘 `662`，只剩 22px，输入框一溢出就压上去 | 列间距改为 `36px`，最小列宽 `280px → 320px` |
| `ColorField` 把色块/十六进制/透明度滑块/百分比硬塞在一行 | 默认 1000px 窗口下「78%」与右列「卡片宽度（0 = 自适应）」重叠 **20×14px** | 透明度滑块另起一行（`α` + 滑块 + 百分比），窄列里不再溢出 |

重构后实测：**1120 / 1000 / 880 三种窗口宽度、外观/布局/日期文案/列表/编辑子页全部 `overlapCount = 0`**，
滑块轨道从 `101px` 恢复到 `195–636px`，`input: null`（不再有数字输入框）。

> 另外两类重叠是误报，已在检查脚本里过滤：Element Plus `filterable` 下拉的隐藏输入框会被拉满整行（运行时不可见）；
> `el-slider__bar` 与滑块按钮本来就叠在一起；SVG 图标内部的路径本来就互相叠放。

> **截图验证的限制**：本轮排查期间桌面会话被锁屏（`LogonUI` 存在、`CopyFromScreen` 报 `handle is invalid`），
> Electron 自带的 `desktopCapturer` 也返回 0 个源，因此改用 **DOM 级量化检查**（`scripts/dom-check.cjs`、`scripts/widget-check.cjs`）：
> 逐文本节点计算对比度（含半透明背景逐层合成、跳过渐变与实心彩色底）、检测横向裁切/页面溢出/标签错位/触达尺寸/空块/被压扁的容器。
> 所有涉及像素的判断都来自 `getComputedStyle` + `getBoundingClientRect`，不依赖肉眼截图。

## 常见问题

**Q：快捷键按了没反应？**
A：`ScrollLock` 可能已被别人（如某些键盘驱动、录屏软件）注册。到「全局设置 → 系统集成」里点录制重新设一个组合键，例如 `Ctrl+Alt+D`；注册失败会弹出提示。

**Q：桌面上怎么换另一个倒数日？**
A：「倒数日列表」里点那一行左侧的「桌面」单选按钮即可；被停用的项不能选中。

**Q：某个倒数日不想跟着全局颜色变了？**
A：进入该项编辑子页，打开「外观覆盖」总开关，再勾选你想改的那几项（例如背景色）。没勾的仍然跟随全局。

**Q：卡片不见了？**
A：托盘图标左键单击切换显示；也可以按快捷键。若位置跑到屏幕外，托盘右键菜单「吸附到右上角」可强制复位。

**Q：设置里改了没生效？**
A：所有改动都是即时生效并写盘的。若桌面卡片没动，检查是否处于隐藏状态（托盘左键唤出），或选中的那一项是否被停用。

**Q：`pnpm run icon` 失败？**
A：该脚本依赖 Windows PowerShell 的 `System.Drawing`。失败时 `resources/` 下若缺少 `tray.png`，托盘会显示空白图标但不影响功能；可手动放一张 16×16 PNG 到 `resources/tray.png`。
