# 首次启动引导

装完第一次打开时弹出的六步引导：语言 → 第一个倒数日 → 外观 → 位置 → 演示视频 → 完成。

## 为什么是独立窗口

引导要有自己的节奏（步骤、跳过、完成），塞进设置窗口当遮罩的话，用户第一眼看到的是
一个「已经有一堆导航」的界面。独立窗口还能自己决定尺寸（无边框、1000×680，
小屏按工作区收缩），并把桌面卡片留在背后当真实预览。

窗口是无边框的（`frame: false`），标题栏的拖动靠 CSS `-webkit-app-region: drag`，
按钮上必须写回 `no-drag`；关闭按钮、Esc、Alt+F4 都走同一条路。

## 「是不是第一次」怎么判

不用 `onboardedAt` 单打独斗，也不能只看配置文件在不在：

- `config-store.initConfig()` 在**创建 electron-store 之前**先 `existsSync(config.json)`。
  store 一落地就会把文件写出来，之后再问永远是「在」。
- 文件已存在（老用户升级上来）→ 把 `runtime.onboardedAt` 补成 1，视为「早就走过」。
  否则升级后所有人都会被补一遍引导。
- 全新安装 → `onboardedAt` 保持 0，`needsOnboarding()` 为真，`bootstrap()` 里开窗口。
- **恢复默认设置保留 `onboardedAt`**：那是「这台机器上的人走过引导」的记录，不是偏好。
  跟着一起清掉的话，重置一次外观就会在下次启动被引导拦一道。
- `--hidden`（开机自启）不弹；`CD_FORCE_ONBOARDING=1` / `CD_SKIP_ONBOARDING=1` 是调试开关。

窗口 `closed` 一律 `markOnboarded()`：点完成、点跳过、直接关窗口，都不该在下次启动再来一遍。

## 每一步都写配置

没有「最后统一保存」：语言、名称/日期、外观、角落、开机自启全都是即时 `patchConfig`。
中途关窗口，改过的部分照样在。名称输入用 320ms 防抖，避免一个字一次写盘；
「下一步」会先把待写的草稿 flush 掉。

**反过来也必须成立：什么都不选，就一个字节都不写。** 从「关于 → 重新查看引导」再走一遍时，
这是硬要求 —— 用户可能只是想看看教程，不是想重新配置。

- 第 2 步记下进入时的原始草稿 `draftBase`，三项全等直接 return。
  只比对归一化后的配置不够：名称为空会被兜底成「未命名倒数日」，那也算一次改动。
- 第 3 步只有点了某一块预设才写。当前外观既不是默认、也对不上任何预设时，
  第一块显示成**「自定义」并且是静态的**（`div` 不是 `button`）——
  点它不会把用户自己调的那套覆盖掉。
- 第 4 步点「已经选中的那个角」直接 return。`snapCorner` 会把偏移量归零，
  而用户此刻只是看了一眼，不该算一次修改。
- 语言点当前语言也直接 return。

验证：`.verify/replay-check.cjs` 造一份「已引导 + 自定义外观 + 偏移量非零」的配置，
从关于页开引导、一路只点「下一步」，比对 `config.json` 前后**逐字节相同**。

第 2 步回填草稿只在**换了倒数日**时做（用 `draftItemId` 记住）。跟着 `config` 一起刷新
会把正在输入的字覆盖掉 —— 每次 patch 都会广播新配置回来。

## 演示视频不是 mp4

`SidebarTourVideo.vue` 是一段按时间轴跑的动效，外面套了一层播放器外壳
（播放/暂停、可拖的进度条、时间码、重播）：

- 镜头 = 「把目标矩形平移到画面中心」+「按 k 缩放」，两者按缩放进度同步插值。
  只用 `transform-origin` 缩放会把目标留在它原本的位置（侧边栏在左边），
  放大后左侧直接被裁掉，标题只剩半个字。
- 目标矩形由 `getBoundingClientRect` 量出、换算成百分比，窗口尺寸变了照样对。
- 字幕按进度分五段，前 10% 是全景、34% 后进入三个子项逐项高亮。
- `prefers-reduced-motion: reduce` 的机器直接停在「已推近」的那一帧，不自动播放。
- 用动效而不是录屏：任何缩放比例下都清晰，还能跟着界面语言（中/英）和四套主题一起变。

画面里的侧边栏用的是真实文案（`nav.groupLook` = 外观与风格），分组结构和设置窗口一致 ——
引导里教的那个位置，点开设置就能对上。

## 预览卡片

`CardPreview.vue` 复用桌面组件那一份 `CountdownCard` 与 `components/card.css`，
只在外面套了一层等比缩放（按容器尺寸算 scale）。抄一份模板的下场是预览和实物慢慢长歪。

`card.css` 是从 `widget.css` 里抽出来的：舞台（`.cd-stage` / `.cd-shrink`）留给组件窗口，
卡片本体三处共用（组件、设置里的预览、引导）。

## 验证

`.verify/onboarding-shot.cjs` 用全新 userData 起真实主进程，逐步点「下一步」出图，
再切英文复一遍关键页，最后点「打开设置」并检查 `config.json` 里的 `onboardedAt`。

两个坑：

- **窗口被遮挡时 `capturePage()` 拿到空白帧**。要加
  `disable-features=CalculateNativeWinOcclusion` 与 `disable-backgrounding-occluded-windows`，
  否则截出来的图只有侧边栏、内容区全空 —— 看起来像渲染 bug，其实是没合成。
- 抓图前先读一次 `.ob-head__step` 的文本，把「第几步」写进日志，能立刻发现点漏了。
