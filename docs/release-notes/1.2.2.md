# 1.2.2

这一版只动「检查更新」：更新源现在可以在界面上选，官方源连不上时不用再去翻配置文件。

1.2.1 把安装向导重做了，但发出去之后暴露一个问题——更新源只有一条写死的 GitHub 地址。国内直连不动的时候，用户除了盯着「更新失败」什么也做不了，连「换个源试试」这条自救路径都没有。界面、行为、安装向导都没改，升级只换更新检查这一块。

## 新增

- **更新源可选**：「关于 → 软件更新」卡片底部多了一行选择器，七个选项——官方 GitHub、gh-proxy.com、gh-proxy.net、gitproxy.click、ghproxy.link、自定义、不使用在线更新。选中即写入配置，点「检查更新」生效，不用重启。
- **自定义地址**：填任意静态直链（对象存储、自己的服务器、内网地址都行）。输入框在**失焦或回车**时才落盘，不会每敲一个字符就把上一次的检查结果清掉。
- **关闭在线更新**：选「不使用」会把更新源清空，此后「检查更新」和启动时的静默检查都不再发任何请求——给完全离线、或不想被打扰的人一个明确开关。

## 变更

- **失败提示按「你能自己解决」的顺序重排**：先让你换源，再提代理，最后才是「手动下载」。原来第一句就是「去改 `runtime.update.proxy`」，那是写给开发者的。
- **镜像返回网页时不再含糊**：有些镜像在目标文件不存在时，不返回 404，而是把自己的首页当 200 吐回来。以前只会说「内容不是有效的 latest.yml」，看起来像清单格式写错了；现在直接说「返回的是网页而不是清单」，并提示先去官方源确认文件已上传。
- **换源会清空上一次的检查结果**：状态回到「还没检查过」，避免旧的「已是最新」误导你以为新源也通了。换完点一下「检查更新」即可。

## 修复

- **出错时地址显示两遍**：错误态下既有一行只读地址、又有输入框里同一串 URL。现在地址只留在输入框里。

## 说明

- **镜像的代价写在界面上**，不藏在文档里：清单和安装包都从同一个第三方端点来，对方可以同时伪造两者，`sha512` 校验在这条链路上不提供保护。它解决的是「连不上」，不是「不安全」。在意就用官方源，或自己托管一份。
- 四个镜像都实测过：既能转发安装包，也支持 `/releases/latest/download/` 这个别名。镜像会挂，所以给的是一串而不是一个——挂了换下一个。
- **地址栏可以一次写多个**，用空格或逗号分隔，会按顺序尝试（前一个不通再试下一个）。下拉只是快捷填充，不限制你写几条。
- 镜像有缓存，刚发布的版本可能延迟可见；急着验证就先切回官方源。
- **更新能不能成功，最终取决于 Release 里有没有 `latest.yml`**。清单和安装包必须放在同一个 Release 里、文件名不能改；只传安装包的话，所有源都会报「更新源不存在」或「返回的是网页」。
- 安装包 110.7 MB，依旧**没有代码签名**，首次运行 Windows 会提示「未知发布者」，这是预期行为，不是安装包损坏。
