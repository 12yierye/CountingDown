# 1.2.2

这一版只改「检查更新」：更新源现在可以在界面上选，官方源连不上时不用再去翻配置文件。

1.2.1 修的是安装向导，但它发出去之后暴露出一个问题——更新源只有一条写死的 GitHub 地址。
国内直连不动的时候，用户除了看着「更新失败」什么也做不了，连「换个源试试」这条自救路径都没有。

## 新增

- **更新源可选**：「关于 → 软件更新」卡片底多了一行选择器，七个选项：官方 GitHub、gh-proxy.com、gh-proxy.net、gitproxy.click、ghproxy.link、自定义、不使用在线更新。换源后点「检查更新」即可，不用重启。
- **自定义地址**：填任意静态直链（对象存储、自己的服务器都行）。地址栏在失焦或回车时才生效，不会每敲一个字符就把上次的检查结果清掉。
- **关闭在线更新**：选「不使用」后更新源清空，检查按钮不再发任何请求——给完全离线、或不想被检查打扰的人一个明确开关。

## 变更

- **失败提示重写**：原来只说「连不上更新源，去改 `runtime.update.proxy`」——那是给开发者看的。现在先让你换源、再提代理、最后才是「手动下载」，按「你能自己解决」的顺序排。
- **出错时不再重复显示地址**：地址现在一直在输入框里，错误态下同一串 URL 出现两遍只是噪音，删掉。
- **镜像「返回网页」时不再含糊**：有的镜像在目标文件不存在时，不返回 404，而是把自己的首页当 200 吐回来。以前只会说「内容不是有效的 latest.yml」，看起来像清单格式写错了；现在会直接说「返回的是网页而不是清单」，并提示先去官方源确认文件已经上传。

## 说明

- **镜像的代价写在界面上**，不藏在文档里：清单和安装包都从同一个第三方端点来，对方可以同时伪造两者，`sha512` 校验在这条链路上不提供保护。它解决的是「连不上」，不是「不安全」。在意的话就用官方源，或自己托管一份。
- 四个镜像都实测过：既能转发安装包，也支持 `/releases/latest/download/` 这个别名。镜像会挂，所以给的是一串而不是一个。
- 镜像有缓存，刚发布的版本可能延迟可见；急着验证就先切回官方源。
- 更新源仍然可以在配置文件里写成多个地址（空格 / 逗号分隔），按顺序试——界面只负责把单个源写进去。
- 安装包依旧**没有代码签名**，首次运行 Windows 会提示「未知发布者」，这是预期行为。
